# Сверка: Android (HushFeed) vs iOS (TikTokRegion)

Таблица разделяет то, что подтверждено исходным кодом HushFeed, и то, что
остаётся непроверенным для iOS.

---

## 1. Компонент: подмена региональных полей

| | Android (HushFeed) | iOS (TikTokRegion) |
|---|---|---|
| **Что известно** | Пишутся только `current_region` и `residence`. `carrier_region`, `sys_region`, `region` читаются, но не пишутся — их меняют хуки геттеров | То же после исправления: пишутся только `current_region` и `residence` |
| **Что не доказано** | Что сервер принимает подмену и отдаёт другой контент | Что те же поля существуют в iOS-версии TikTok и что сервер на них реагирует |

## 2. Компонент: региональные поля на iOS

| | |
|---|---|
| **Что известно** | В Android-версии поля передаются в query string и JSON-теле. HushFeed перехватывает `CommonParamsTTNetHandler` |
| **Что не доказано** | Что iOS-версия использует те же имена полей и тот же механизм сборки параметров. Внутренние классы iOS обфусцированы и не проверялись |

## 3. Компонент: сетевые классы TikTok

| | |
|---|---|
| **Что известно** | `TTHttpTask`, `TTNetworkManagerChromium`, `AWESecurityConfig`, `AWEAPMManager`, `GULAppEnvironmentUtil` — из исходников `tuxi/TikTok-Tweaks` и `haoict/tiktok-god` |
| **Что не доказано** | Что эти классы существуют в текущей версии TikTok на iOS. Ни один не проверялся на устройстве. Селекторы могут быть переименованы R8 |

## 4. Компонент: момент изменения параметров запроса

| | |
|---|---|
| **Что известно** | HushFeed вызывает `requestParams(Map)` в конце сборщика параметров — после того, как приложение их заполнило |
| **Что не доказано** | Что iOS-версия имеет аналогичную точку входа. В `TikTokRegion.m` ищется метод с суффиксом `params:` — эвристика, а не подтверждённый факт |

## 5. Компонент: согласование языка, региона и часового пояса

| | |
|---|---|
| **Что известно** | HushFeed подменяет `Locale.getDefault()`, `TimeZone.getDefault()`, `sys_region`, `timezone_name` и `timezone_offset` согласованно |
| **Что не доказано** | Что iOS-версия читает те же источники. `CTCarrier` мёртв с iOS 16. `NSTimeZone` и `NSLocale` живы, но не проверялись |

## 6. Компонент: подпись и проверка запросов

| | |
|---|---|
| **Что известно** | Заголовки `X-Gorgon`, `X-Argus`, `X-Ladon`, `X-Khronos` связывают параметры запроса. Изменение `region` без пересчёта подписи может привести к отказу |
| **Что не доказано** | Что подпись вычисляется из тех же полей на iOS. Если да — подмена региона сломает подпись, и запрос будет отклонён |

## 7. Компонент: загрузка iOS-твика

| | |
|---|---|
| **Что известно** | Твик внедряется в расшифрованный IPA, переподписывается и ставится через Sideloadly. Требует: расшифрованный IPA, theos, ldid, insert_dylib, Sideloadly |
| **Что не доказано** | Что собранный dylib загрузится в TikTok. Нет устройства, нет расшифрованного IPA, нет инструментов сборки |

## Итог

| Компонент | Статус |
|---|---|
| Подмена региональных полей | ✅ Сверено с HushFeed, исправлены 5 ошибок |
| Региональные поля на iOS | ❓ Не проверено — нужен перехват на устройстве |
| Сетевые классы TikTok | ❓ Не проверено — имена из старых проектов |
| Момент изменения параметров | ❓ Не проверено — эвристика по сигнатуре |
| Согласование языка и пояса | ❓ Не проверено — источники не подтверждены |
| Подпись запросов | ❓ Не проверено — риск отказа не исключён |
| Загрузка твика | ❌ Заблокировано — нет IPA и устройства |

**Блокер:** расшифрованный IPA. Без него нельзя собрать dylib, внедрить его
и проверить загрузку. Все остальные неизвестные пункты проверяются только
на устройстве.

**Следующий шаг:** получить расшифрованный IPA (с джейлбрейкнутого устройства
или из доверенного источника), собрать dylib через theos, внедрить через
insert_dylib, подписать через Sideloadly и проверить загрузку на устройстве.
