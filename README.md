# TikTokRegion

Библиотека для iOS, меняющая региональные параметры запросов TikTok.
Аналог HushFeed для Android, порт на Objective-C.

---

## Статус: не проверено в TikTok

**Ни разу не запускалось внутри TikTok.** Библиотека собрана и
проверена на сборочном уровне, но никто не видел, чтобы она меняла
что-то в реальном приложении.

Главная неизвестная: **существуют ли в текущей версии TikTok классы,
на которые навешиваются хуки.** Имена обфусцированы и меняются от
версии к версии. Если их нет — библиотека загрузится, отработает
конструктор и спокойно ничего не сделает.

## Что делает

Подменяются ровно два поля — `current_region` и `residence`.
Плюс `carrier_region_v2`, но только если там ровно три цифры (MCC).
Поля `region`, `sys_region`, `carrier_region` не трогаются.

Запросы входа (`/passport/`) обрабатываются отдельно: подмена там не
применяется, живые значения устройства возвращаются на место. Иначе
аккаунт выглядел бы переехавшим за секунду.

Полная таблица правил — в `COMPARISON.md`.

## Устройство

```
Tweak/RegionLogic.h      вся логика подмены. Чистый C99, 47 тестов.
Tweak/TikTokRegion.m     мост в Objective-C. Собственной логики
                         подмены не содержит — только хуки.
Tools/patcher/           установщик для Windows (Rust, без зависимостей).
Harness/                 приложение, проверяющее подмену вне TikTok.
```

Логика лежит в C намеренно: её можно скомпилировать и запустить на
любой машине, без Xcode и без устройства. ObjC-мост — тонкая обёртка,
поэтому тесты проверяют именно тот код, что попадёт в dylib.

## Сборка

Требуется macOS с Xcode — на Windows iOS-библиотеку не собрать.

```bash
clang -arch arm64 -isysroot $(xcrun --sdk iphoneos --show-sdk-path) \
      -miphoneos-version-min=15.0 -fobjc-arc -O2 -dynamiclib \
      -framework Foundation -framework Security -framework UIKit \
      -install_name "@executable_path/TikTokRegion.dylib" \
      -o TikTokRegion.dylib Tweak/TikTokRegion.m
```

Без Mac — через GitHub Actions: вкладка Actions, запуск workflow,
артефакт через ~10 минут.

### Почему arm64

Это разные архитектуры, а не «старое и новое». Подменяется App Store
IPA, а он собран под arm64 даже на arm64e-устройствах (A14+). arm64e
нужен для джейлбрейк-пути. Смешивать нельзя — у каждой свой
package-конфиг.

## Установка

Нужен **расшифрованный** `TikTok.ipa`. Из App Store файл приходит
зашифрованным: после вставки библиотеки приложение не запустится.

```powershell
# установщик сам найдёт телефон, подпишет файл и поставит
.\tiktok-region-installer.exe путь\к\TikTok.ipa
```

Архив установщика: `releases/download/v1.0.0/TikTokRegion-setup.zip`

## Проверка

Нужен компилятор C99 — `zig` подойдёт и умещается в одну папку.

```powershell
# указать путь один раз в этой сессии
$env:ZIG = "C:\путь\к\zig.exe"

node Tools/test-region-logic.mjs    # 15 проверок + запуск C-тестов
node Tools/test-tweak.mjs           # 37 проверок структуры ObjC
node Tools/test-objc-compile.mjs    # 15 проверок компиляции
node Tools/test-build-levels.mjs    # 5 проверок уровней сборки
```

67 проверок и 47 настоящих C-тестов.

Без `zig` три теста из четырёх упадут с «компилятор не найден» —
остальные проверки не требуют его, но C-тесты запустить нечем.

`Tools/Shim` — минимальное описание Foundation для проверки синтаксиса
на Windows. Он доказывает, что код разбирается и типы сходятся, но
**не** доказывает, что настоящий Foundation ведёт себя так же.
