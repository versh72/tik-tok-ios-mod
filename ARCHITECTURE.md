## 3. Почему «мод работает без VPN» — неверная формулировка

Она широко повторяется в Android-сообществе, но не подтверждается кодом.

Ни в одном из ~10 прочитанных проектов нет:
- встроенного прокси или библиотеки туннелирования
- правки hosts-файла
- собственного сетевого стека

Список из 30+ пунктов в описании мода на apkw.ru **не содержит ни одного
сетевого пункта** — только UI, загрузка видео, авторизация, биллинг, root.

Правильная формулировка: **мод меняет то, что приложение сообщает серверу о
себе, но трафик идёт тем же путём.** Он не может работать без сети. Он может
работать без *ручного переключения* — и именно это означает `免拔卡`
(«免» — не надо переключать вручную), а не «без VPN».

Собственная инструкция в `i90O/tiktok-ios-ipa` подтверждает это: шаг 5
*«打开Shadowrocket添加节点，开启科学联网»* — добавить узел и включить прокси.

## 4. Архитектура того, что реализуемо

Цель — не подмена цели, а её разложение на части и реализуемая часть.

```
Исходная цель:  «TikTok показывает актуальный контент в РФ без ручного VPN»
        │
        ├─► [НЕРЕАЛИЗУЕМО]  изменить поведение TikTok
        │     └─ причина: подпись iOS, Team ID, потолок iOS 17.0
        │
        ├─► [НЕРЕАЛИЗУЕМО]  изменить ответ сервера
        │     └─ причина: серверная политика, клиентский код её не меняет
        │
        └─► [РЕАЛИЗУЕМО]  диагностировать, где именно ломается путь
              └─ DNS · TLS · HTTPS · сравнение двух конфигураций
```

### Что уже реализовано в этом репозитории

Swift-пакет `NetDiag` — 24 исходных файла, 114 unit-тестов, 84 статические
проверки. Три независимых слоя:

```
┌──────────────────────────────────────────────────────────┐
│  NetDiagUI         SwiftUI: 4 экрана, ViewModel          │
├──────────────────────────────────────────────────────────┤
│  NetDiagEngine     Network.framework:                    │
│                    DNS · TLS · HTTPS · NWPathMonitor      │
├──────────────────────────────────────────────────────────┤
│  NetDiagCore       чистая логика.                        │
│                    Нет SwiftUI, нет Network, нет UIKit    │
│                    ← единственное, что трогают тесты       │
└──────────────────────────────────────────────────────────┘
```

`NetDiagCore` не содержит ввода-вывода — поэтому весь набор тестов запускается
без устройства и симулятора.

### Ключевые инженерные решения

**1. Короткое замыкание на первой причине.**

```
DNS ──► TLS ──► HTTPS
 │
 └─► упал? → TLS и HTTPS пропускаются,
              отчёт говорит «DNS», а не «TLS»
```

Если DNS не отвечает, TLS тоже не ответит. Сообщать «TLS failed» — значит
отправить читателя не туда. Проверяется тестом
`testDNSFailureStopsLaterStagesAndIsReportedAsDNS`.

**2. TLS-проверка не отключается.**

```swift
if SecTrustEvaluateWithError(trust, &trustError) {
    verdict.isAcceptable = true
} else {
    verdict.isAcceptable = false
    verdict.failureReason = describeTrustFailure(trust, error: trustError)
}
complete(verdict.isAcceptable)      // ← никогда не безусловный true
```

Инструмент, доверяющий любому сертификату, сообщил бы «всё хорошо» ровно на
пути, который он ищет — туннеле, терминирующем TLS своим сертификатом.
Отказ здесь **и есть результат**.

**3. Сравнение двух конфигураций вместо одного замера.**

```
Запуск A  «VPN выкл»   example.com → DNS ✓  TLS ✓  HTTPS 200
Запуск B  «VPN вкл»    example.com → DNS ✓  TLS ✗  (untrusted root)
                       ─────────────────────────────────────────
                       изменилось: passed → failed, tlsCertificateRejected
```

Один замер не различает «сломано устройство» и «сломан путь». Два — различает.
Это и есть полезный результат.

**4. Ничего не покидает устройство.** Эфемерная сессия, cookies отключены,
кэш `nil`, тела ответов читаются на 4 КиБ и выбрасываются, строки запросов
отбрасываются на этапе разбора, свободный текст редактируется перед записью.
Ничего не сохраняется на диск.

## 5. Почему не веб-клиент и не другая соцсеть

Явное требование брифа. Обоснование:

| Подмена | Почему отвергнута |
|---|---|
| Веб-клиент | Не показывает ленту TikTok. Подменяет цель |
| Сторонняя соцсеть | Не TikTok. Подменяет цель |
| VPN-клиент | Прямо исключён в брифе |
| Диагностическое приложение | **Единственное, что не подменяет цель**, а отвечает на вопрос «почему лента пуста» |

Диагностика отвечает на подвопрос исходной задачи, который и является
блокирующим: различает ли сбой серверную региональную политику от сбоя
маршрутизации. Это различие определяет, есть ли вообще смысл в дальнейших
действиях.

## 6. Чего в архитектуре сознательно нет

| Не построено | Почему |
|---|---|
| Детекция VPN | Требует платного entitlement. Угадывать по типу интерфейса — ложь |
| Перехват трафика | Требует root CA на устройстве, снижает безопасность всех приложений |
| Снятие TLS-доверия | Сообщило бы «здоровье» на том самом сломанном пути |
| Логика, специфичная для TikTok | Приложение измеряет путь, а не приложение. Домены TikTok в списке пресетов означали бы, что вывод — вердикт о TikTok, а это не так |
| Сохранение истории | Нечего сохранять; сохранение — обычный источник утечек |
